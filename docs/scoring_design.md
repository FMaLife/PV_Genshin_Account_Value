# Scoring Design

เอกสารนี้อธิบายวิธีคำนวณคะแนนตัวละครและคะแนนรวมของบัญชี (Account Value)

---

## หลักการโดยรวม

คะแนนของบัญชี = ผลรวมคะแนนของ**ตัวละครที่ผู้เล่นเป็นเจ้าของจริงเท่านั้น**
(อ้างอิงจาก `data/raw/player_owned_characters.csv`) — ตัวละครที่ผู้เล่นไม่มี
จะไม่ถูกนำมาคิดคะแนนเลย ไม่ใช่การให้ 0 คะแนนแล้วรวมเข้าไป

คะแนนของตัวละคร 1 ตัว ประกอบด้วย 3 ส่วน:

```
character_score = main_score + secondary_score + constellation_bonus
```

---

## 1) Tier Score

แปลง Tier จาก Game8 (Main Tier List) เป็นตัวเลข:

| Tier | Score |
| ---- | ----- |
| SS   | 100   |
| S    | 80    |
| A    | 60    |
| B    | 40    |
| C    | 20    |
| D    | 10    |

ตัวละคร 1 ตัวอาจมีได้หลาย Role (Main DPS / Sub-DPS / Support) แต่ละ Role มี Tier
ของตัวเอง — เลือก Role ที่ Tier สูงสุดเป็น **main_score** ส่วน Role ที่เหลือ
เอามารวมกันแล้วหารครึ่ง เป็น **secondary_score** (ให้ role รองมีน้ำหนักน้อยกว่า
role หลัก แต่ก็ยังมีคุณค่าอยู่บ้าง)

```
main_score      = max(tier_score ของทุก role)
secondary_score = sum(tier_score ของ role ที่เหลือ) / 2
```

## 2) Constellation Bonus

### แนวคิดตั้งต้น (จากประสบการณ์ผู้เล่นจริง)

- Constellation **ทุกระดับ** (ไม่ว่า Game8 จะติดดาวให้หรือไม่) เพิ่มดาเมจพื้นฐาน
  ให้ตัวละครประมาณ 15-20% ต่อระดับ — ควรได้คะแนนพื้นฐานเท่ากันหมด
- Constellation ที่ Game8 **ติดดาวแนะนำ** มักไม่ใช่แค่เพิ่มดาเมจเฉยๆ แต่เปลี่ยน
  playstyle หรือทำให้เล่นง่ายขึ้นแบบก้าวกระโดด (เช่น C2 ของ DPS บางตัว, C6 ของ
  Support บางตัว) — ควรได้คะแนนโบนัสเพิ่มเติมนอกเหนือจากคะแนนพื้นฐาน
- Constellation ที่แนะนำมักไม่มาครบ 1-6 (เช่น มาแค่ C1, C2, C4) เพราะงั้นต้องคิด
  แบบสะสมทีละระดับ ไม่ใช่เลือกแค่ "ตัวที่ดีที่สุด" ตัวเดียวแบบ V1
- Constellation ไม่ควรมีน้ำหนักมากเกินไปเมื่อเทียบกับ Tier เพราะต่อให้ C6 เต็ม
  ก็แค่ทำให้ตัวละครแรงขึ้นในระดับเดียวกับการ "อัพ 1 ขั้น Tier" เท่านั้น (เช่น
  Jean/Raiden ที่ recommended constellation รวมกันได้ ~8 ดาว มักถูกมองว่า
  อัพเทียร์ได้ 1 ขั้นพอดี ไม่ใช่อัพหลายขั้น)

### สูตร

Constellation ใน Genshin สะสมกัน (มี C4 = มี C1, C2, C3, C4 ครบ) จึงคิด
คะแนนแบบสะสมทีละระดับตั้งแต่ C1 ถึงระดับปัจจุบันของผู้เล่น:

```python
BASE_LEVEL_RATE = 0.02        # 2% ของ tier_score ต่อ 1 ระดับ C ที่มี (ไม่ว่าจะติดดาวหรือไม่)

STAR_EXTRA_RATE = {
    1: 0.01,                  # ติดดาว 1 ดวง ได้เพิ่มอีก 1%
    2: 0.02,                  # ติดดาว 2 ดวง ได้เพิ่มอีก 2%
    3: 0.03,                  # ติดดาว 3 ดวง (เปลี่ยน playstyle) ได้เพิ่มอีก 3%
}

MAX_CONSTELLATION_RATE = 0.20 # เพดานรวม 20% ของ tier_score (≈ อัพ 1 ขั้น Tier)

for lvl in 1..current_constellation:
    rate += BASE_LEVEL_RATE
    if lvl ติดดาวใน Game8:
        rate += STAR_EXTRA_RATE[จำนวนดาว]

rate = min(rate, MAX_CONSTELLATION_RATE)
constellation_bonus = round(main_score * rate)
```

### ตัวอย่าง

**Zibai** (SS, tier_score = 100), Game8 แนะนำ C1(★★), C2(★★★), C4(★★),
ผู้เล่นมี **C4**:

| Constellation | Base | Star Extra | Rate สะสม |
| -------------- | ---- | ----------- | ---------- |
| C1             | 2%   | +2% (2★)    | 4%         |
| C2             | 2%   | +3% (3★)    | 5%         |
| C3             | 2%   | ไม่ติดดาว   | 2%         |
| C4             | 2%   | +2% (2★)    | 4%         |

รวม rate = 15% (ไม่ชนเพดาน 20%) → `constellation_bonus = round(100 * 0.15) = 15`

**Furina** (SS), ผู้เล่นมี **C0** → ไม่มีระดับ C ให้สะสมเลย → `bonus = 0`

## 3) Scope: คิดเฉพาะตัวละครที่ผู้เล่นมี

`calculate_account_score()` วนจาก `player_owned_characters.csv` เป็นหลัก
(ไม่ใช่วนจากตัวละครทั้งหมดในฐานข้อมูล Game8) ตัวละครที่ไม่มีในไฟล์นี้จะไม่ถูก
นำมาคิดคะแนนเลย เพราะ "ไม่มีตัวละครนี้" ควรมีผลต่อคะแนนบัญชีต่างจาก
"มีตัวละครนี้แต่ C0" — กรณีแรกไม่ควรมีคะแนนอะไรเข้ามาเลยแม้แต่ tier score พื้นฐาน

---

## Design Decisions ที่ยังเปิดอยู่ (สำหรับ V3+)

- `STAR_WEIGHT` / `BASE_LEVEL_RATE` / `MAX_CONSTELLATION_RATE` เป็นค่าเริ่มต้น
  ที่ตกลงกันไว้คร่าวๆ ยังปรับได้ตามข้อมูลจริงที่เก็บมาเพิ่ม
- ยังไม่รวมคะแนนจาก Weapon และ Artifact เข้ามาในสูตร (ตามที่ระบุไว้ใน
  `scraper_game8.md` ว่ายังไม่เก็บข้อมูลส่วนนี้)
- แผนดึง `current_constellation` ของผู้เล่นแบบอัตโนมัติผ่าน Enka.Network API
  แทนการกรอก CSV มือ (ดูรายละเอียดใน `data_model.md`)
